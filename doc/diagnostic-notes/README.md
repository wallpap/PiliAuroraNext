# 历史排障经验

日常排查见[维护与排障](../maintenance/troubleshooting.md)，采用策略见[默认构建与策略](../development/build-defaults.md)。逐次调查、版本对照和设备数据保存在本地 `doc/dev/`，按[实验资料归档](../../tool/experiments/README.md#实验资料归档)整理。

## 播放与直播

- 分离音视频的读取中断可能被已有缓存掩盖。分别检查音视频时钟、选轨、网络和缓存，覆盖长缓存耗尽；只看整体 buffering 容易漏掉音轨停滞。
- 退出挂起先记录最后完成的关闭阶段，再检查路由、TickerMode、会话、卸载和输出释放。调用方超时与原生释放分别确认。
- Surface 重建时，旧引用释放失败须保留所有权并停止重建；新资源完整创建后才登记，失败回滚。主机故障注入覆盖协议，实际设备另验。
- 更新退出须经过进度保存和播放器释放，再关闭存储。强制结束可能丢失最后进度。
- 黑闪先对齐版本、故障时刻、会话、程序路径和纹理身份。输出代次增长不能证明重新分配纹理，帧消费回执也不能证明引擎已成功导入或画面正常。
- 超分重建同时检查实际硬解后端、有效纹理、音频时间线和播放意图；候选探测报错与最终后端失败分别判断。原生交接见[Windows 视频输出](../maintenance/windows-video-output.md)。
- 分片 seek 持续读取越过后续分片边界，并覆盖先前跳、再回退的顺序；仅检查落点可能漏掉中途跳包。固定样片见[分片回退探针](../../tool/probes/README.md#windows-分片独立音轨回退回归)。
- 画面边缘色偏按时间戳对齐新帧，分别比较整帧、最坏行与局部误差。整帧均值可能掩盖单行异常；离屏结果不能直接推广到 HDR、其他 GPU 或最终呈现。

## 弹幕与帧呈现

- 更新次数、Build/Raster、GPU 提交和实际呈现分别观测，保留目标时间、回调时间、位移与 present 的同帧关联。缺失数据不借相邻帧补齐。
- 同时看逐帧间隔和跨帧窗口内的速度误差、呈现延迟。长短帧交替可能保持正常平均速度。运动位置使用帧目标时间，暂停及资源期限使用实际单调时间。
- 固定视频、目标帧率、刷新率与解码路径，分别测取图、提交和显示；同一视频帧的重复绘制无需重复读取。CPU 亲和性收益依赖设备调度。
- EGL 时间戳不能补回已错过的 deadline。呈现关联缺失时，只能确认已观测到的出帧与生命周期；回退、暂停、隐藏和恢复分别验证。
- 媒体时钟的后台读取仍需在返回时核对播放器、媒体、seek 和释放代次。稳定播放与页面、全屏切换分别统计，更新空档不能直接换算为显示丢帧。

## 内存与诊断开销

- Private、RSS、私有工作集、Dart 堆、图片缓存和图形分配分别记录。名义像素字节不包含全部驱动与中间资源，不能跨口径求和。
- 分配栈表示首次提交路径，未必是当前所有者。核对 DLL/PDB 身份，并在释放后持续观察；资源计数归零与进程内存回落可能发生在不同时刻。
- 图片解码核对下载尺寸、实际像素、活动引用与原生资源。累计解码帧数不等于同时驻留量；退出监听也不等于纹理已释放。
- 固定源码身份、输入和缓存条件，同时比较峰值与可见延迟。完整解码后裁剪不能证明解码峰值降低，检查点采样也不能代替全程峰值。
- 任务名额限制并发，输出预算限制计账像素；完整帧回退、decoder 工作区、Flutter/ANGLE 上传及窗口合成仍需分别观察。
- 诊断会干扰测量。分别测采集、读取、脱敏、编码和落盘成本，避开采样边界；同内容、同设备的受控对照用于判断回归。
- 缓存监听和清理回调按对象身份核对。取消或隐藏后检查在途任务排空；原生清理未确认时继续持有资源屏障。
- 区域像素比较统一色彩空间、色度对齐和采样邻域。CPU 样片的无缝结果不能覆盖任意输入或 GPU 缩放，worker 退出与父进程上传资源释放分别验收。

## 首页加载

首屏耗时拆为黑名单同步、内容请求、合作作者补查、过滤发布、视口补位和图片加载，分别记录耗时与数量。过滤删除与视口不足分别判断，App/Web 分页沿各自协议检查。

列表预加载区末项可能引发连续分页，动画骨架可能扩大重绘范围。分别检查实际可视区、分页触发和绘制隔离；响应完成与慢帧相邻只能缩小排查窗口。当前入口见[功能地图](../development/features.md#首页与内容发现)。

## 构建与状态

- 可执行文件遇到目录写入拒绝时，除 ACL 外也检查进程与文件的完整性级别，DACL 的 FullControl 不覆盖完整性策略。
- 比较状态管理方案时，固定页面、请求、缓存和生命周期，分别测订阅、数据转换、分配与帧耗时。隐藏后仍需管理计时器、网络和原生资源，框架迁移本身不能证明性能改善。
- CI 同时报告关键路径和 runner 总用时，分开计量缓存下载、解压、依赖准备与编译。冷启动、系统缓存和后台负载会影响单次结果，多 ABI 串行耗时不能直接换算为矩阵收益。
