# 播放器状态模型与反例检查

本模型用于检查播放器周边的业务归属、异步命令、输出和时间线。对应实现是
`PlaybackSession`、`NativePlaybackRuntime`、播放器门面及输出协调器；模型覆盖业务状态与交接协议，原生解码、GPU 呈现和设备行为通过设备探针验证。

投屏路由持有 `DlnaSession`。离页立即撤销结果交付，等待搜索启动或设备命令完成后释放资源。仅在设置地址和播放均确认后切换当前设备。投屏地址查询固定视频账号，由视频路由检查当前分 P 和结果归属。

点播路由创建并释放详情和对应的简介控制器；转场标识只用于动画，不用于查找状态。评论、AI 总结和音频路由通过受当前视频、分 P 与页面生命周期约束的操作回调与点播互动。共享播放器的桌面窗口交接由当前路由提供，返回下层路由时恢复其交接入口。

点播元数据请求发起时捕获主账号及凭据代次。应用结果和继续异步处理前都检查凭据代次与当前播放归属。只在两者仍有效时更新续播分 P、字幕和看点，公开字幕回退沿用同一归属检查。

## 状态空间

把系统写为带时间的转换系统 `M = (S, E, δ)`：`E` 是用户命令、查询回执、原生事件、
超时及资源释放，`δ(S, e)` 产生新状态。每个 `await` 都是允许其他事件插入的调度点。

```text
S = (phase, stage, owner, g, request, load, runtime, output,
     plan, intent, inhibitors, desired, applied, revisions, pending,
     activeOperation, pendingOperations, writer, seekSequence, pendingSeek, anchor, failure, action,
     pendingEOF, progressWatch, recoveryIncident, healthySince, nativeIdentity,
     snapshotVersion, routeGeneration, routeInhibitor, owners, keepalive, released)
```

| 符号 | 源码含义 |
| --- | --- |
| `owner, g` | 当前页面所有者及其失效代次 |
| `request, load` | 来源查询代次、实际原生加载代次；配置重载可保留 request，但必须改变 load |
| `runtime, output` | 原生运行时身份与输出代次 outputEpoch |
| `desired, applied` | 已接受的目标配置、已获得成功回执的配置 |
| `revisions[k], pending` | 每个配置键的修订号、尚未结算或等待加载的键 |
| `intent, inhibitors` | 用户播放意图，以及页面和会话分别持有的抑制令牌 |
| `activeOperation` | 调度器正在排空的操作；调用方终结后，原生操作仍可能在执行 |
| `writer` | 单独串行协调播放/暂停意图的写入器；最终原生互斥由运行时保证 |
| `seekSequence, pendingSeek` | 最新跳转代次及其尚未结算的等待，包括提交资格与原生命令回执 |
| `anchor` | 媒体位置与单调时间的只读锚点 |
| `pendingEOF` | 当前接受请求中，等待加载结算的本次原生打开结束事件 |
| `progressWatch` | 当前有效播放区间的非外推位置基线、无推进的截止时间及是否已观察到推进 |
| `recoveryIncident, healthySince` | 按内容累计的恢复次数、活跃耗时与当前连续健康窗口的起点 |
| `nativeIdentity` | 当前 runtime 的原生文件身份是否仍可验证，不随换片重置 |
| `snapshotVersion` | 会话发布的状态版本，门面用它拒绝过期投递 |
| `routeGeneration, routeInhibitor` | 点播页面的交接代次及等候恢复时持有的抑制令牌 |
| `released` | Player 实际释放屏障，不能用 shutdown 的调用方超时代替 |

## 不变量与活性条件

### I1：归属与代次

操作的提交条件为：

```text
valid(op, S) = ¬closing ∧ ¬disposed ∧ op.owner = owner ∧ ¬owner.closed
              ∧ op.request = request ∧ op.load = load
              ∧ op.g = owner.g（使用页面 guard 的异步结果）
```

普通控制命令还要求 `phase = ready ∧ ¬owner.requiresLoad`。查询和加载使用各自的
接受请求对象及 deadline。实际原生操作已经开始时可以排空，但返回后的规范状态写入
必须再次检查有效性。页面切换前的媒体结束事件不能变成新页面的完成动作。

原生文件事件还必须经过 playlistEntryId 与文件 binding 核对；输出事件须匹配
`(runtimeId, loadId, outputEpoch)`。不同层的身份不能相互替代。

### I2：意图和事实分离

```text
effectivePlaying = mediaReady ∧ ownerLoaded ∧ intent.playing
                   ∧ sessionInhibitors = ∅ ∧ ownerInhibitors = ∅
```

加载阶段仅在当前加载进入意图协调时允许 `mediaReady` 成立。原生 play/pause 成功只
确认命令写入，`actual.playing` 仍由观测事件更新。令牌释放只能移除持有者的抑制，
不能将用户暂停改为播放。旧 writer 的成功或失败都不能结算新修订的调用方。

当 writer 尚有在途写入时，即使重复指令与当前观测相符，调用方仍须等待最新指令落实。
解除页面或会话抑制时，令牌立即移除，等待原生写入的回执受同一命令时限约束。
回执超时后，writer 继续排空在途写入并落实有效意图。

独立音频 Player 通过 `AudioSessionHandler` 的租约栈接管声音。当前租约持有视频会话
抑制，等待视频或前一音频的暂停回执后才播放；系统焦点变更串行执行并重新检查归属。
音频页关闭等待创建、open 和 Player 销毁，销毁失败继续持有抑制。系统中断只影响有效
播放，拔耳机更新暂停意图；duck 结束只恢复尚未被用户修改的音量。

系统媒体服务将相对跳转的待确认目标与已发布位置分开：连续点击和长按共用最新目标累计，
位置确认后回到真实时间线；最新命令失败、媒体替换和控制回调交接使目标失效，旧失败
不能清除新目标。长按周期任务在松开、切源、回调交接或通知释放时停止。

上下曲通过随媒体条目保存的 `MediaNavigation` 进入业务层。视频复用分 P、合集、PGC
及本地列表的切集规则，独立音频复用列表切换并等待打开回执。调度前检查页面存活、
账号及播放归属，通知只发布当前媒体已注册的导航能力；释放页面按精确 owner 移除条目。

独立音频创建抛出 `NativePlayerCreationFailure` 时，仍须等待其 `released` 回执确认
已分配句柄释放。清理未确认时，本页拒绝再次创建，关闭继续持有租约；后续页面先等待
租约交接，再分配 Player，避免旧原生资源尚未释放就创建新的播放器。

音频路由通过类型化参数交接初始音量和视频位置回写，由页面实例创建并释放
`AudioController`。页面拥有动画与弹层；控制器拥有曲目、跳段订阅、系统媒体控制和原生
Player 释放。关闭路由后拒绝旧请求及旧系统回调，租约仍等待真实释放。

### I3：配置收敛与真实结算

对配置键 `k`：

```text
commit(k, r) ⇒ r = revisions[k] ∧ commandCurrent ∧ native.applied
terminal(k, r) ∧ r = revisions[k] ⇒ k ∉ pending
```

第二式适用于已经提交的控制命令；加载期间接受的配置仍可等待完整计划落实。
旧修订的失败不能清除新修订的 pending。相同目标值只有已确认应用时才能直接返回
`applied`；前次失败后必须允许重试，已有请求未完成时不能提前宣告成功。

同内容切源继承最新用户配置后，Session 通过同步的 `configurationForPlan` 核对来源约束；
排队结束、候选轮换和加载期间的配置合并也执行该核对。播放器门面在已知源尺寸超过
屏幕物理尺寸时清除计划中的超分 shader，避免先用旧超分渲染新源首帧、再重载关闭。
尺寸允许的切源保留当前超分档位，其他配置仍按修订合并。

### I4：互斥、时限与释放

```text
|运行时执行中的原生操作| ≤ 1
|某操作槽的排队请求| ≤ 1
deadline = acceptedAt + budget
调用方取消/超时 ⇏ 原生操作已结束 ⇏ 原生资源已释放
createNextPlayer ⇒ previousPlayer.released 已成功完成
```

解析、排队、初始化、打开、输出确认和意图协调共享接受时的总预算；新阶段不能
重新获得整份预算。取消和异常不能毒化串行链。关闭先拒绝新操作，运行时排空、卸载、
释放输出并销毁 Player；只有真实释放回执才能归还资源槽。

同一次关闭共享一个回执和一个截止时间。截止前观测到 `released` 即可确认关闭成功，
清理方法报告成功后仍须取得 `released`。清理失败或截止时间先到时，调用方取得
`cleanupIncomplete`。之后收到真实释放时，会话进入 `disposed`，已交付回执保持原结果。
`disposed` 是吸收态，迟到的清理结果无法修改终态。

Windows 降分辨率、转为纯音频或加载尺寸未知的新源时，旧媒体卸载后再回收渲染器中的
中间资源。同尺寸切源及尺寸未知的同源恢复复用渲染器；降画质与超分变更重合时只重建
一次，重建失败不打开新文件。尚无源几何时使用 1×1 占位输出，原生几何确认后设置
最终限幅尺寸，并等待该尺寸的首帧回执才进入 ready，避免首次高分辨率输出先扩容再缩小。
输出尺寸、原生资源释放计数和进程内存须分别验证。

Windows 每次加载交接在旧文件卸载屏障后，通过跳过绘制的 render 消费 mpv 延迟
reconfig/reset，避免旧帧引用跨到下一次解码器分配。新 load 首个有效共享纹理复制须
确认 GPU 完成，才发布帧及当前 token 的消费身份；等待最多 100ms，失败保留未消费状态。
普通帧沿用异步复制，不能用逐帧等待换取较低峰值。暂停、取消、失败恢复、EOF 和
不同 GPU 的实际画面仍须使用设备探针检查。

活性检查有明确前提：底层操作最终返回时，最新且未超时的请求应可继续执行。
若底层永不返回，调用方仍须在 deadline 终结，但不能为追求继续播放而提前释放资源。

```text
接受更新的 seek，或当前加载进入 ended / failed
  ⇒ 未结算的旧 seek 立即返回 superseded
已提交的旧 seek 仍占用执行器，直到原生回执到达
```

等待原生提交资格时同样执行跳转失效规则。暂停保留当前跳转，切源与关闭分别按请求取代与关闭协议结算。

### I5：终态一致性

```text
phase = failed ⇒ failure ≠ null
LoadResult.failed(f) ⇒ 当前失败快照含有同一原因 f
action.completed.owner = 已加载媒体的业务所有者
```

第二式仅在该请求仍是当前请求时适用。被新请求取代的结果不能改写新状态。
结束、失败和关闭均停止媒体时间外推。

当前请求未结算时，归属匹配的原生终止错误同时结算请求和快照，沿用同一个 `failure`。
取消只使未结算回执失效，不意味着原生操作已排空；迟到的 open 或 play 成功不能恢复 `ready`。
若 `LoadResult.ready` 已交付，后续原生错误只改变当前快照，不追溯修改旧回执。

### I6：媒体时间与输出交接

对锚点 `A = (p₀, t₀, rate, advancing, ready, continuity, ttl)`：

```text
p(t) = null                                      if ¬ready
p(t) = p₀                                        if ¬advancing
p(t) = p₀ + round(rate × clamp(t − t₀, 0, ttl))  otherwise
```

`rate` 必须有限且大于零。暂停、缓冲、seek 或终态先冻结/失效锚点；恢复后等待新采样。
同一连续域内的旧采样不能覆盖新采样；seekSequence、load 与 owner 改变时隔离旧锚点。

输出尺寸有独立的目标值与已确认值；一次通道调用返回不代表 Flutter 已消费新帧。
保护截图先进入呈现场景，再修改原生几何，消费确认后才撤图；失败且无法确认恢复时
继续保留保护图。源代次失效后旧回执不得更新新源尺寸。

### I7：全屏目标与已确认状态

全屏包含 `target`、`confirmed` 和 `transition` 三种状态。Windows 可以在窗口放大前
预先提交全屏布局；该布局是待确认状态，不能将其等同于原生窗口已经切换成功。

```text
transition 成功 ⇒ confirmed := target
transition 失败 ⇒ UI 回到先前 confirmed
转换期间收到新目标 ⇒ 排空当前转换后落实最新目标
```

进入失败后仍须允许重新进入，退出失败后仍须允许重新退出。页面内全屏不要求原生
窗口放大，但仍需要正确处理进出、失败和并发目标。

### I8：自动续播位置属于媒体的有效区间

来源查询、首次加载、页面恢复和自动重载中的续播位置应满足：

```text
live ⇒ startPosition = reloadPosition = null
非直播 ∧ 已知有效 duration ⇒ 0 ≤ resumePosition < duration
当前媒体确认完播 ∨ resumePosition < 0 ∨ resumePosition ≥ duration ⇒ 续播起点 = 0
```

未知或非正时长不能用作上界。原生观测到的有效时长按内容身份保存，不能借用上一视频的
时长裁剪新视频。初次加载才确认提示时长偏长时，纠正后的重新加载仍属于原请求，沿用
同一个 deadline；从 0 仍失败时正常终结，不得循环重开。显式 seek 到片尾的结束语义
与自动续播分开处理。
最后一帧时间戳可以小于总时长。确认完播后，重播、同源续播和页面退出前保存的续播点
均从零开始，是否立即播放仍由当前意图决定。提前 EOF 若进入恢复流程则保留中断点。

### I9：进度投影只接受当前加载

时间显示和进度条共享一个投影，区分预览、观测和完播：

```text
可提交 = owner 已加载 ∧ load = 已确认的 load ∧ phase ∈ {ready, ended}
P := 当前原生位置      if 可提交 ∧ phase = ready ∧ 无在途 seek 命令
P := 已确认的 EOF 位置 if 可提交 ∧ phase = ended ∧ 无在途 seek 命令
P 保持预置值或上次值   otherwise
时间显示位置 = P
进度条位置 = 当前拖动目标 if 正在拖动 else P
完播 = 当前 owner 已加载 ∧ phase = ended
```

加载就绪或 seek 命令结算时立即同步位置与缓冲边界，不要求实际落点接近请求目标。原生位置、时长和
缓存通知只触发重新读取当前值，通知携带的旧数据不能覆盖新的时间线。完播位置冻结，
卸载复位不能回写；完播先提交状态，再上报历史，不随后发送普通进度。

会话快照异步交付。同一 load 内也可能排队多个快照，门面只采用当前 owner 的最新 `snapshotVersion`。
播放状态回调、保活、画中画和恢复探测都随已采用的快照更新。完成动作保留到会话确认，
因此跳过过期快照仍可处理当前完成动作。

未知时长只保留最新的待提交跳转，时长判断不使用显示层取整。切换来源、切换 owner
或退出时撤销等待与拖动预览。完播后的播放命令直接重开，不依赖跳转能力或已知时长。

### I10：加载结算不得丢弃同代 EOF

原生文件和输出准备、Session 写入播放意图是两个回执。原生层会合并同一文件的重复 EOF；
Session 不能假设进入 `ready` 后原生层还会再发一次。

```text
k := (runtime, owner, request, load)
EOF(k) ∧ k = 当前打开 ∧ phase ∈ {loading, recovering} ⇒ 暂存首个 EOF(k)
加载及意图确认成功 ∧ k 仍有效 ⇒ 消费暂存 EOF(k)
失败、超时、请求被取代或重新打开 ⇒ 丢弃旧打开的 EOF
```

消费沿用 `ready` 后的判定：网络点播提前断流保留播放意图与中断点并进入恢复；确认完播
则提交完成动作。`LoadResult.ready` 表示加载和意图已经获得所需回执，快照可能已因 EOF
进入结束或恢复。原生输出尚未准备便收到 EOF 时，仍由原生加载结算为失败。

### I11：跨内容的不可播放有独立作用域

```text
nativeIdentity = unknown ⇒ 同一 runtime 不发起新的原生 open
切换内容、来源或网络 ⇏ 新 runtime ∨ 释放屏障已通过
sessionInhibitors ≠ ∅ ⇒ 切换 owner 后仍不允许有效播放
```

原生事件队列溢出可使文件身份不可再验证；这条路径与来源是否可访问无关。此时不能清除
身份标记或跳过释放屏障来强行打开下一文件。会话级抑制则允许加载确认成功，但播放意图
不落实为原生播放。两者都可能跨视频持续，和单次加载的 EOF 不同，须按快照及运行时日志区分。

首次失去身份时，原生层以 `native-lifecycle` 结算待确认的加载，并通知当前非退休文件所属的会话。
随后到达的准备回执不能使加载成功。重复身份错误只触发一次通知。旧文件身份与卸载信息仍用于验证
原生资源释放。

### I12：恢复预算的健康窗口

```text
healthy = ready ∧ effectivePlaying ∧ actual.playing
          ∧ 未缓冲 ∧ 无待结算或原生进行中的 seek ∧ 所需轨道均在推进
同一故障、同一加载中 healthy 连续 10s ⇒ 清除该故障的恢复预算
healthy 中断 ⇒ 丢弃健康窗口起点
```

恢复次数和已用预算跨同一故障的重载累计。重载、暂停、抑制或 seek 会中断健康窗口，
恢复后从当前观测重新计满十秒。所需轨道由当前媒体能力和仅音频配置决定。

### I13：页面交接按代次结算

离页和返回均推进页面交接代次。恢复结果写入页面前须核对代次、播放 owner 及媒体身份。
当前代次负责释放本次捕获的抑制令牌，即使媒体已经变化或加载失败。
再次离页会把令牌留给下一次恢复，旧回执不能提前恢复播放或确认页面状态。

### L1：已就绪且要求播放时，启动必须有限结算

`ready` 只确认加载及意图协调，不代表媒体已经推进。首次自动播放、主动播放、最后一个抑制令牌释放，
或显式 seek 结算后，若仍需播放，则开始观察当前加载的原生位置：

```text
eligible = phase = ready ∧ effectivePlaying ∧ 无待结算的 seek 命令
advance = actual.playing = true ∧ actual.buffering ≠ true
          ∧ 两个可比较的原生位置属于同一加载，且后者严格大于前者
eligible 持续到截止时间 ∧ 未观察到 advance ⇒ failed(observe-playback-start)
```

截止时间从本次观察开始计 15 秒。`playing=true`、缓冲通知和重复播放请求不能证明推进或延长时限；
外推位置不作为证据。seek 的原生观测未确认时不能比较位置；确认后的首个读数只作为新基线。
暂停、抑制、新加载或离开 `ready` 使旧观察失效；恢复有效播放时重新计时。已有恢复、EOF 或错误转换
先发生时，以其结果为准。此条件假设 Dart 事件循环能交付定时器及原生观测。

### L2：首次推进后仍须持续观测

```text
advance ⇒ deadline := now + 30s
eligible 持续到 deadline 且未再次推进 ⇒ failed(observe-playback-stall)
```

首次推进不结束观察。计时到期时再读一次当前原生位置，允许没有状态回调的播放继续。
缓冲通知与重复位置不延长时限。已有的网络、音轨及视频恢复路径可以提前处理故障，
新加载独立计时。位置推进只保障媒体时钟的活性，音轨健康和实际出帧仍需各自证据。

### L3：原生跳转必须确认落点或报告失败

```text
确认落点 ⇒ 原生文件身份与 seekSequence 同时匹配
当前文件未终止，提交 seek 后 5s 仍无匹配落点 ⇒ failed(observe-native-seek)
```

命令回执只确认原生接受了跳转。落点超时时保留原生提交屏障，不把下一次跳转与旧事件混配。
迟到的真正确认可解除屏障，但不会把会话从失败改回就绪；重试须经正常卸载和重新加载。
已经换源、完播或进入关闭的旧跳转不会再发布该超时。

## 检查方法

1. 沿源码调用关系为每个事件列出提交条件、状态写入和异步边界。
2. 选取会打破不变量的最短事件序列，例如“失败 → 相同配置重试”、
   “旧媒体加载 → 新页面接管 → 旧媒体 EOF”、“旧意图写入 → 新意图 → 旧写入抛错”。
3. 在实际会话/运行时接口注入可控回执，先运行失败用例，再修改实现。
   EOF 回归分别安排在加载回执前、意图回执前、`ready` 后，并组合完播、提前断流、失败和换代；
   运行时作用域通过一次身份故障后尝试不同内容键和来源来检验。
   [核心时序模型](../../test/plugin/pl_player/playback/playback_core_model_test.dart)用可控时钟和 `PlaybackSession`
   实例执行启动入口与观测的有限组合，并单独检查截止前中断、seek 落点和错误到达顺序。
   [命令交错模型](../../test/plugin/pl_player/playback/playback_interleaving_model_test.dart)在一次原生 seek 尚未返回时，
   穷举暂停、更新 seek、切源的 6 种顺序，以及加入关闭后的 24 种顺序。每条轨迹检查回执、
   下一次原生提交和旧 EOF、旧失败的影响。另检查当前 EOF 或失败与 seek 提交前、提交后的组合。
   连续切源时，只允许最新有效请求等待原生执行器，并检查它在截止前、到期时及到期后收到旧回执的结果。
4. 修复后重新沿模型检查，新反例继续补充回归。
5. 最后一轮没有新的可确认反例，且相关回归与静态检查通过，才结束本轮审查。

## 验证边界

主机测试穷举测试中声明的输入组合，不穷举整个播放器状态空间，也不假定原生事件一定能到达。
Android Surface/MediaCodec、Windows 纹理/GPU 的真实呈现、音频焦点和系统全屏效果
通过目标设备验证，并记录设备、输入和结果。
