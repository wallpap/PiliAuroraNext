# Delete Comment

1. 检查 `git status --short` 和 `git diff`，记录本次 Git 基线。用户未指定范围时覆盖全部第一方源码和配置，按目录分批；扫描和逐条审查分别进度登记。
2. 从仓库根按[注释棘轮入口](../../../tool/README.md#注释棘轮)运行 Dart 与非 Dart 两条命令的 `--inventory` 和 `--stats`，可选传入目录或文件。读每条注释、相关代码和测试；连续注释可组成一条语义记录，但台账必须覆盖每个 token。
3. 为每条注释记录原文件、行号、分类和处理结果：
   - **Tautology**：代码已表达同一事实，删除。
   - **Stale**：经源码或历史核对已不适用，删除。
   - **Excuse**：注释用于说明仍存在的变通或债务。先查重并建立 GitHub issue，写明源码、影响、验收条件，再删除；不在清理中暗改行为。若不能立项，保留注释并报告原因。
   - **Decision Record**：代码看不出的现行取舍或约束，迁入 [ADR](../../../doc/adr/README.md) 再删除；关联设计可共用一份 ADR。
4. 保留生成内容、许可证、来源署名和具有工具语义的指令；将受保护的条目标为例外。若某项不确定，保留在存量并说明。按项目约定将逐条台账放在 `doc/dev/`，仅将稳定资料纳入版本控制。
5. 复跑两条棘轮和统计，以本次工作开始前的提交执行 `--check <基线>`，再运行 `git diff --check` 与受影响测试。交付分类数量、实际减少的源码行、剩余可删行上限、issue/ADR 和未覆盖范围。每个盘点项都须有处理结果；待人工审查的条目不计入已分类。
